# Local Kubernetes demo with Docker Desktop

The backend URL comes from the `usage-backend-config` ConfigMap generated by the
base Kustomize configuration.
The upstream API key and Django secret key come from the `usage-backend-secrets` Secret.
To use a different upstream base URL, edit the `API_URL` literal in
`apps/usage-backend/k8s/kustomization.yaml` and reapply `k8s/demo`.

## 1. Enable Kubernetes in Docker Desktop

Open **Docker Desktop → Kubernetes → Create cluster**, choose **Kubeadm**, then
**Create → Install**. Wait until the cluster is running.

## 2. Build the two app images

Run these commands from the repository root with Docker Desktop running:

```sh
brew install kubernetes-cli
kubectl config use-context docker-desktop
kubectl --context docker-desktop get nodes

docker build -t usage-backend:local apps/usage-backend
docker build -t cypienta-web:local -f apps/web/Dockerfile .
```

## 3. Create upstream credentials and deploy

```sh
mkdir -p "$HOME/.config/cypienta-demo"
chmod 700 "$HOME/.config/cypienta-demo"
openssl rand -base64 48
nano "$HOME/.config/cypienta-demo/real-upstream-secrets.env"
```

Copy the generated value into `DJANGO_SECRET_KEY` and enter your real API key,
replacing both placeholders:

```dotenv
API_KEY=<your real upstream API key>
DJANGO_SECRET_KEY=<paste the generated value here>
```

Save and close the editor, then restrict access to the file:

```sh
chmod 600 "$HOME/.config/cypienta-demo/real-upstream-secrets.env"
```

Continue deployment:

```sh
kubectl --context docker-desktop --namespace default create secret generic usage-backend-secrets --from-env-file="$HOME/.config/cypienta-demo/real-upstream-secrets.env" --dry-run=client -o yaml | kubectl --context docker-desktop --namespace default apply --server-side -f -
kubectl --context docker-desktop --namespace default apply -k k8s/demo
kubectl --context docker-desktop --namespace default rollout restart deployment/usage-backend
kubectl --context docker-desktop --namespace default rollout status deployment/usage-backend --timeout=120s
kubectl --context docker-desktop --namespace default rollout status deployment/web --timeout=120s
```

## 4. Open the app and inspect its Pods

Open **http://localhost:8080**. The frontend Service is a `LoadBalancer` on port
`8080`; Docker Desktop exposes it on localhost. No app port-forward process or
kind port-mapping file is needed.

In **Docker Desktop → Kubernetes**, select namespace **default**. Inspect the
two Deployments and three app Pods. `usage-backend` should have two Ready copies.
Backend readiness checks the real upstream, so a missing/invalid API key or an
unreachable upstream keeps the backend Pods unready.

| Address or component                                | Purpose                                  |
| --------------------------------------------------- | ---------------------------------------- |
| `http://localhost:8080`                             | Kubernetes Usage Dashboard               |
| `http://localhost:8080/api/user/info`               | Frontend → wrapper → real upstream check |
| `usage-backend` Service                             | Stable address for two wrapper Pods      |
| `usage-backend-config` ConfigMap                    | Real upstream base URL                   |
| `~/.config/cypienta-demo/real-upstream-secrets.env` | Private upstream credentials             |

To inspect or remove only this app:

```sh
kubectl --context docker-desktop --namespace default get deployments,pods,services
kubectl --context docker-desktop --namespace default delete -k k8s/demo
kubectl --context docker-desktop --namespace default delete secret usage-backend-secrets
```

Docker Desktop's **Stop** or **Reset cluster** controls affect the whole built-in
cluster. App removal commands above leave other Kubernetes workloads alone.

## Optional: Headlamp and CPU/memory readings

Docker Desktop is the main interface. Headlamp is available for its topology map,
logs, and events: open the desktop app and select **docker-desktop**, then
**Workloads → Pods**, namespace **default**.

```sh
brew install --cask headlamp
kubectl --context docker-desktop apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl --context docker-desktop --namespace kube-system rollout status deployment/metrics-server --timeout=120s
kubectl --context docker-desktop --namespace default top pods
```

If Metrics Server reports a kubelet certificate validation error in this local
Docker Desktop demo, the local-only workaround is:

```sh
kubectl --context docker-desktop --namespace kube-system patch deployment metrics-server --type=json -p='[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--kubelet-insecure-tls"}]'
```

[Headlamp desktop](https://headlamp.dev/docs/latest/installation/desktop/),
[Metrics Server](https://github.com/kubernetes-sigs/metrics-server).
